# Bounded-page governance replay plan

> Proposed additive library increment. The existing complete-prefix verifier remains the reference path. This increment removes its fixed 10,000-leaf input ceiling for a single process without treating a serialized cache as proof.

## Ground truth and gap

`src/replay.ts` currently copies at most 10,000 leaves and 32 MiB into one call, starts from the independently pinned anchor every time, and returns a public snapshot that omits the authority key-use ledger, Merkle frontier, operation IDs, accepted checkpoint index and actor predecessor leaf. That snapshot cannot safely resume verification. `src/authority-lifecycle.ts` keeps important anti-reuse state inside opaque `AuthorityState`. The observer source protocol pages leaves 64 at a time and checkpoints 16 at a time. A checkpoint can cover several leaf pages, so fetched pages are tentative until the enclosing signed checkpoint is verified.

## Contract

Add a browser-safe opaque in-process `GovernanceReplaySession`, created by verifying the signed anchor against an independently supplied pin and checking the signed size-zero checkpoint. It accepts ordered canonical leaf pages with a per-call bound and separately seals the next immediate signed checkpoint only when the tentative frontier size **equals** that checkpoint's declared size. The caller must request no more than `min(64, nextCheckpoint.size - tentativeSize)` leaves, or buffer excess bytes without applying them before the checkpoint seal. This preserves the historical authority state at each checkpoint and lets a later action observe that checkpoint. The implementation reuses the complete-prefix verifier's exact leaf, actor, receipt, authority and checkpoint predicates; it must not diverge into a second protocol. Page addition mutates only tentative session state and cannot advance the exported accepted snapshot. A failed append or seal poisons the session; callers must discard it and re-create from retained evidence. An accepted checkpoint snapshot has the same meaning and limitations as `GovernanceReplaySnapshot`: authenticated prefix, not global freshness or product-effect truth.

The session retains the complete in-memory authority state, history frontier, accepted checkpoint hashes, all operation IDs, per-actor latest signed action/leaf identity and any other history needed for predecessor receipts. It checks each `observedCheckpointHash` and previous receipt against already sealed checkpoints. A checkpoint may cover more than one page; the provider signing key may rotate in an intervening customer-root-signed revision leaf. The caller provides no untrusted serialized state. Both Node and browser imports stay supported; no database, Node built-in or third-party runtime dependency enters this API.

The observer can construct a fresh session from retained exact evidence after a cold start. Reconstructing from genesis has linear cost and may eventually exceed a Hobby invocation's time budget; when that occurs, a process-local session alone does **not** make the feed reliably auditable across invocations. The observer must surface incomplete coverage and may resume fetching/staging without claiming acceptance. This increment addresses library input size, not observer catch-up readiness. A future observer-owned durable continuation would be a trusted local cache with fenced transactional custody, not a cryptographic substitute for fresh replay. Its design is deliberately deferred until benchmark evidence and the observer store contract justify the added state/indexing complexity. Fresh full replay must remain possible for an independent auditor.

## Test-first implementation

1. Add a failing session test against the missing API: real pinned genesis and mixed authority/action/checkpoint history, page sizes below the method bound, a checkpoint spanning multiple pages, and snapshot remaining at the prior accepted head before seal. Observe red.
2. Add negative tests for a page that crosses a checkpoint boundary, a following action that observes that just-sealed checkpoint, wrong page order, changed/noncanonical leaves, skipped/forked checkpoint, unauthorized signer after rotation, stale/duplicate operation ID, future observed head, divergent or changed prior receipt, and failure after tentative pages. Every intended check must fail for its own reason. Mutate a key predicate and confirm the targeted test fails, then restore.
3. Exercise more than 10,000 leaves over multiple calls with real signed checkpoints and a representative mix of authority revisions and signed actions; compare the final history root/snapshot to independent construction. Track runtime and memory at 100, 1,000 and 10,000 leaves; report hardware/runtime and do not infer a production service-level guarantee from one machine.
4. Preserve `replayGovernanceHistory` and make it use the same verification engine or prove equivalence with the session on all adversarial fixtures. Run tests, typecheck, build, browser-root smoke, diff check and independent spec/quality review before publishing.

## Naming and scope

Keep `src/replay.ts` as the sole owner of mixed-history validation. Public names should communicate that the session is process-local and that only a sealed checkpoint is accepted. Do not export mutable internals or offer `importSnapshot` in this increment. The observer owns transport, page retention and scheduling; this library owns cryptographic replay. No 1Bridge app source changes are part of this increment.
