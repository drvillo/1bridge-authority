# Process-local bounded-page governance replay

`createGovernanceReplaySession(signedAnchor, expectedPin, signedGenesis)` verifies the independent customer pin and the size-zero signed checkpoint before returning an opaque in-process session. `appendLeaves(page, nextCheckpoint)` copies at most 64 ordinary byte arrays and at most 256 KiB per call. It binds every tentative page to the exact same next checkpoint, refuses a page that crosses that checkpoint's declared size, and applies the same revision, actor, receipt and Merkle predicates used by `replayGovernanceHistory`. `sealCheckpoint(nextCheckpoint)` resolves without a snapshot only at exact size equality and after verifying the historical provider key, authority root, policy epoch and history root. `snapshot()` lazily builds and caches the frozen actor-head view for the last sealed checkpoint and throws after any failed or concurrent call. A failed session must be discarded and rebuilt from retained exact evidence.

The complete-prefix API still limits its input to 10,000 leaves, 10,001 checkpoints and 32 MiB. It now drives the same session engine with bounded internal pages. A process-local session can replay a longer feed without importing or trusting a serialized cache. It retains authority state, the frontier, accepted checkpoints, all operation IDs, and only each actor's latest predecessor action leaf in memory. Tentative actor updates are held separately until seal, so a snapshot requested during append cannot reveal unsealed actor heads. Checkpoint sealing merges only changed actors; sorting all actor heads occurs only when `snapshot()` is explicitly requested. `verifyReceipt(receipt, leafBytes)` checks a separately supplied integrated receipt against an exact checkpoint already authenticated by this session and the completion leaf's RFC inclusion. Call this asynchronous method sequentially with all other session methods; overlapping calls, including two receipt checks, poison the session. It returns false for unknown, tentative, divergent or mismatched evidence; a false result alone is not an accusation against the source because the receipt may be forged or the observer may still be catching up. It does not establish independent receipt custody, prove the application effect, or verify source freshness. The session does not survive a process restart, and it does not establish complete coverage during an observer outage. A cold auditor can replay retained evidence from genesis; reliable catch-up within a Vercel Hobby invocation remains an observer-level question.

The unit suite covers tentative-versus-sealed snapshots, a checkpoint spanning two pages, a following action that observes the newly sealed checkpoint, exact-size and target equality, crossing boundaries, changed and noncanonical bytes, input copying across an asynchronous call, skipped/forked checkpoints, historical key rotation, duplicate operation IDs, future observed heads, changed predecessor receipts, page limits and concurrent misuse. It also rejects two unlinked same-key actions in one tentative checkpoint. Existing complete-prefix adversarial fixtures exercise the same engine. The 10,004-leaf test includes a signed actor binding, an action, provider rotation and 10,001 root-signed policy revisions. It compares the final checkpoint root with independent `merkleRoot(leaves)`, rejects that input through the legacy bounded API, and accepts it through the session.

On 2026-10-14, a full-suite run on Apple M4 Pro (arm64, 48 GiB RAM), Node 26.5.0, generated and signed the 10,004-leaf evidence in 8.84 s. Replay elapsed time from session creation was 50 ms at 100 leaves, 472 ms at 1,000, 4,663 ms at 10,000, and 4,665 ms at 10,004. Sampled V8 heap at those points was 28.5, 19.8, 23.1 and 24.4 MiB respectively; these are non-monotonic GC-affected snapshots, not peak RSS or an observer deployment budget. The test's duration was 13.51 s. One machine and one feed shape cannot establish a production latency bound, especially for histories with many actor receipts or a much larger active authority map.

A separate full-suite run with eight actors, 256 receipt-linked actions and 34 signed checkpoints generated evidence in 1.15 s and replayed it in 467 ms on the same host. The sampled V8 heap after replay was 15.1 MiB. This shape exercises latest-predecessor replacement, same-key receipts and repeated seals, but it is not a high-cardinality capacity test or a peak-memory measurement. The session's all-operation-ID and all-checkpoint ledgers remain linear in feed history; longer histories and high actor counts still need observer-specific capacity assessment.

The new API test first failed because the root export did not exist. An input-mutation test then failed when caller-owned leaf bytes changed during an asynchronous hash; copying bytes before the first await made it pass. A concurrent-call test failed because the first call reported success after the second poisoned the session; checking the failed flag before returning made it pass. Deliberately relaxing seal size equality caused the exact-size test to fail with the wrong error; the equality rule was restored. The compiled root module performed a pinned genesis, tentative append and signed seal in Chromium, Firefox and WebKit.

The follow-up API test first failed because `sealCheckpoint` returned an eager snapshot. A deliberate mutation that removed tentative predecessor lookup caused the same-key-in-one-checkpoint test to fail; the lookup was restored. After restoration, `pnpm test` passed 501 tests in 18 files, `pnpm typecheck`, `pnpm build`, `git diff --check` and the three-file advisory smell scan passed. The compiled root module performed a pinned genesis, tentative append and signed seal with the void-return API in Chromium, Firefox and WebKit. The package has no lint, `typecheck:gate`, persistence integration or E2E script; those gates apply when app/observer persistence and routes are changed. Independent specification and quality review remain separate from these local checks.
