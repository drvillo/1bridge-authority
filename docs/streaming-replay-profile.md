# Process-local bounded-page governance replay

`createGovernanceReplaySession(signedAnchor, expectedPin, signedGenesis)` verifies the independent customer pin and the size-zero signed checkpoint before returning an opaque in-process session. `appendLeaves(page, nextCheckpoint)` copies at most 64 ordinary byte arrays and at most 256 KiB per call. It binds every tentative page to the exact same next checkpoint, refuses a page that crosses that checkpoint's declared size, and applies the same revision, actor, receipt and Merkle predicates used by `replayGovernanceHistory`. `sealCheckpoint(nextCheckpoint)` accepts the head only at exact size equality and after verifying the historical provider key, authority root, policy epoch and history root. `snapshot()` reports only the last sealed checkpoint and throws after any failed or concurrent call. A failed session must be discarded and rebuilt from retained exact evidence.

The complete-prefix API still limits its input to 10,000 leaves, 10,001 checkpoints and 32 MiB. It now drives the same session engine with bounded internal pages. A process-local session can replay a longer feed without importing or trusting a serialized cache. It retains authority state, the frontier, accepted checkpoints, operation IDs, actor heads and predecessor action leaves in memory. It does not survive a process restart, and it does not establish source freshness, service effects, independent observation or complete coverage during an observer outage. A cold auditor can replay retained evidence from genesis; reliable catch-up within a Vercel Hobby invocation remains an observer-level question.

The unit suite covers tentative-versus-sealed snapshots, a checkpoint spanning two pages, a following action that observes the newly sealed checkpoint, exact-size and target equality, crossing boundaries, changed and noncanonical bytes, input copying across an asynchronous call, skipped/forked checkpoints, historical key rotation, duplicate operation IDs, future observed heads, changed predecessor receipts, page limits and concurrent misuse. Existing complete-prefix adversarial fixtures exercise the same engine. The 10,004-leaf test includes a signed actor binding, an action, provider rotation and 10,001 root-signed policy revisions. It compares the final checkpoint root with independent `merkleRoot(leaves)`, rejects that input through the legacy bounded API, and accepts it through the session.

On 2026-10-14, a focused 10,004-leaf run on Apple M4 Pro (arm64, 48 GiB RAM), Node 26.5.0, generated and signed evidence in 8.90 s. Replay elapsed time from session creation was 54 ms at 100 leaves, 522 ms at 1,000, 7,038 ms at 10,000, and 7,040 ms at 10,004. Sampled V8 heap at those points was 28.4, 21.0, 23.2 and 24.5 MiB respectively; these are non-monotonic GC-affected snapshots, not peak RSS or an observer deployment budget. The test's total duration was 15.94 s. One machine and one feed shape cannot establish a production latency bound, especially for histories with many actor receipts or a much larger active authority map.

The new API test first failed because the root export did not exist. An input-mutation test then failed when caller-owned leaf bytes changed during an asynchronous hash; copying bytes before the first await made it pass. A concurrent-call test failed because the first call reported success after the second poisoned the session; checking the failed flag before returning made it pass. Deliberately relaxing seal size equality caused the exact-size test to fail with the wrong error; the equality rule was restored. The compiled root module performed a pinned genesis, tentative append and signed seal in Chromium, Firefox and WebKit.

After restoration, `pnpm test` passed 499 tests in 18 files, `pnpm typecheck`, `pnpm build` and `git diff --check` passed, and the four-file advisory smell scan reported no findings. The package has no lint, `typecheck:gate`, persistence integration or E2E script; those gates apply when app/observer persistence and routes are changed. Independent specification and quality review remain separate from these local checks.
