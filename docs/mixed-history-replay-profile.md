# Pinned mixed-history replay profile

`replayGovernanceHistory(signedAnchor, expectedPin, leaves, checkpoints)` checks one complete retained feed prefix. The caller supplies an independently authenticated customer anchor pin, the exact signed anchor, all canonical leaf bytes from index zero, and every signed checkpoint from size-zero genesis through the selected head. It returns a frozen `GovernanceReplaySnapshot` with the accepted size, final checkpoint statement hash, current authority commitment/revision/policy, and the last action statement hash for each actor signing key. The caller must retain the original evidence. A later page is checked by replaying the retained prefix plus that page; a serialized snapshot is not an authenticated resume token.

The verifier reconstructs the history root incrementally, so each accepted head is an extension of the exact same retained leaf prefix. It authenticates the genesis against the pinned anchor, follows the immediate checkpoint predecessor links, folds customer-signed authority revisions in leaf order, applies provider-key rotations before checking the enclosing checkpoint signature, and verifies actions against the authority state at their own leaf. It rejects duplicate operation IDs, unknown observed heads, stale/revoked actors, and unknown leaf kinds. Each actor signing key has one ordered action stream: a later action must name the last accepted action hash and supply an integrated receipt whose exact signed checkpoint was already accepted on the same chain, is no later than the actor-observed head, and includes the exact retained predecessor leaf. Actor-key streams do not imply a total order across different actors.

The input is bounded to 10,000 leaves, 10,001 checkpoints, 32 MiB of copied canonical evidence, 24 KiB per leaf and 1 KiB per checkpoint. Input arrays must be dense ordinary arrays with data entries. Leaves must be ordinary `Uint8Array` values. Signed records are copied through the canonical codec before asynchronous verification. No database adapter, Node built-in, or runtime dependency enters the browser export.

An accepted snapshot proves a pinned **prefix** of signed commitments and historical authority. It does not establish that a database effect happened, that an intent/effect opening is truthful, that the head is globally fresh, that the provider never presented another fork, or that an unpublished isolated action does not exist. A later same-key action can expose a missing predecessor; an independent receipt or checkpoint copy can expose equivocation or an isolated hidden tail. The observer must label its fixed target provisional until replay authenticates the historical provider key that signed it. The library cannot turn source-only polling into proof of global completeness.

The verifier uses constructive append-only root reconstruction from retained leaves, rather than accepting source-provided consistency proofs. The existing `consistencyProof` and `verifyConsistency` functions can produce portable RFC-style evidence between accepted checkpoints. A fresh complete-prefix replay is deliberately linear in leaf count and checkpoint count, with cryptographic signature costs for each revision, action and checkpoint. The planned 100/1,000/10,000-leaf benchmark remains necessary before promising a Vercel catch-up envelope.

Verification evidence for this increment is in `test/replay.test.ts`, including mixed two-actor history, policy and provider rotation, historical signer and authority mismatches, forked/missing checkpoints, suppressed same-key predecessors, divergent prior receipts, duplicate operations, revoked actors, future observed heads, malformed arrays and noncanonical leaf bytes. These are pure cryptographic composition tests; they do not replace product transaction or observer persistence tests.
