# Independent observer report profile

The portable `signObserverReport` and `verifyObserverReport` functions define a version-1, canonical, purpose-bound P-256 statement by an independently operated observer. The report is an attestation by the observer, not a self-contained proof of replay, a service freshness oracle, or a claim that every completed event worldwide was seen. An operator must pin the observer public key outside the provider application and independently pin the customer authority anchor.

## Statement

The exact signed envelope is `{statement,signature}`. The statement contains `version:1`, `coverageScope:'verified_prefix'`, `feedId`, `anchorPin`, `observerKeyId`, `coveredCheckpointHash`, the full provider-signed `coveredCheckpoint`, `authorityRevision`, `authorityRevisionHash`, nullable `observerPolicyHash`, `checkedAt`, `knownReceipts`, and `unresolvedFindings`. The embedded checkpoint names the exact covered `size`, `historyRoot`, `authorityRoot` and `policyEpoch`. `checkedAt` is an exact UTC millisecond timestamp such as `2026-10-14T12:00:00.000Z`; it describes the observer's verification time, not a guarantee that the source is still at that head.

`knownReceipts` is `{kind,count,digest}`. `kind:'none'` requires zero and null, so an observer with no independent archive cannot imply hidden-tail reconciliation. `kind:'known_archive'` names only the **known** independently retained set, never all completed operations. `unresolvedFindings` is `{count,digest}` and must include every currently unresolved finding in the observer's retained store when the report is issued. Zero count requires a null digest; positive count requires a lowercase 32-byte hash. `observerEvidenceSetDigest` computes each nonempty set digest as SHA-256 of UTF-8 `1bridge.authority/v1/observer-evidence-set\n` followed by the exact canonical JSON encoding of the sorted, duplicate-free array of lowercase 64-character hashes; it accepts at most 20,000 entries. Its fixed-width encoder preserves those bytes beyond the general 1 MiB canonical-record limit. Receipt entries are `completionReceiptHash` values. `observerFindingHash` computes each finding entry as SHA-256 of UTF-8 `1bridge.authority/v1/observer-finding-id\n` followed by exact retained canonical finding evidence bytes. The independent archive and durable report store must use these helpers; a caller-supplied digest is currently an observer attestation, not recomputed by the pure signing helper.

`signObserverReport` requires the claimed anchor pin to equal the pin retained in the replay result. It also compares that result to the exact embedded checkpoint hash, feed, size, authority root and policy epoch before signing; the caller must supply a snapshot produced by pinned full-history replay, not mutable source metadata. It signs with the `observer.coverage` purpose and checks that the supplied P-256 pair matches. `verifyObserverReport` checks exact syntax, the embedded checkpoint hash, expected feed and anchor pin, the independently trusted observer key ID and the purpose-bound signature. It does **not** replay the retained leaves/checkpoints, verify the historical provider signing key or independently recompute the receipt/finding digests. A verifier seeking stronger assurance must obtain the observer's retained evidence and replay it under the same customer pin.

The separate observer implementation may retain externally supplied receipts and bind the known set and its unresolved statuses to signed reports. Without such receipts it uses `knownReceipts:{kind:'none',count:0,digest:null}`. A signed source-only report can establish what an independent observer says it verified at a specific head and time. It cannot reveal a coherent hidden tail never disclosed to any independent participant. A later source response does not automatically clear a previously unresolved finding.
